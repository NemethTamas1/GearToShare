# Ratings Migration

> **Fájl:** `database/migrations/..._create_ratings_table.php`
> **Kapcsolódó dokumentumok:** [01. Model](./01.Model.md) · [03. Business Logic](./03.BusinessLogic.md)

## Mezők

| Mező | Típus | Megkötés | Megjegyzés |
|---|---|---|---|
| `id` | `bigIncrements` | PK | |
| `rental_id` | `foreignId` | NOT NULL, FK → `rentals.id`, `cascadeOnDelete()` | melyik bérléshez tartozik |
| `rater_id` | `foreignId` | NOT NULL, FK → `users.id`, `cascadeOnDelete()` | az értékelő |
| `rated_id` | `foreignId` | NOT NULL, FK → `users.id`, `cascadeOnDelete()` | az értékelt |
| `score` | `unsignedTinyInteger` | NOT NULL | 1-5, a tartományt a `StoreRatingRequest` (`between:1,5`) ellenőrzi |
| `comment` | `text` | NULLABLE | opcionális szöveges értékelés |
| `timestamps` | `created_at`, `updated_at` | | |

## Egyedi kulcs

```php
$table->unique(['rental_id', 'rater_id']);
```

Egy bérlést egy fél csak egyszer értékelhet. Ez a controller `422`-es ellenőrzése mögötti **második védelmi szint**: ha a controller-ellenőrzés hibázna, a tábla akkor sem engedi a duplát (de `500`-at okozna `422` helyett).

## Foreign key viselkedés

Ha a bérlés vagy az érintett user törlődik, az értékelések is törlődnek (`cascadeOnDelete`), konzisztensen a `gears` és `rentals` táblákkal. Ez később felülvizsgálandó, ha az értékelések megőrzése fontossá válik.

## Átlag: nem tárolt adat

Az átlagos pontszám **élőben számolódik** a `ratings` táblából, nincs rá oszlop. A `users.renter_rating` és `lender_rating` oszlopok jelenleg **használaton kívül** vannak.
