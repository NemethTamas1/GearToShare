## Áttekintés

Öt lépéses, mobil-first modal az eszköz-feltöltéshez, a `Home.tsx`-ről a "Bérbe adnék" gombbal nyitható meg. A kategóriafüggő mezők (3. lépés) egy deklaratív séma alapján, dinamikusan renderelődnek — nem kategóriánként külön, hardcode-olt komponensekkel.

## A séma — `data/categorySchemas.ts`

```ts
export const CATEGORY_SCHEMAS: Record<Category, CategoryField[]> = {
  hand_tool: [],
  cordless: [battery_capacity_mah, modes],
  corded: [power_w, modes],
  machine: [load_capacity_kg, fuel_type, fuel_tank_l, horsepower],
};
```

A `StepAttributes` ebből olvassa ki, mely mezőket kell renderelnie az aktuálisan kiválasztott kategóriához — új kategória/mező felvételekor **csak ezt a fájlt** kell bővíteni, a step-komponenseket nem.

**A `CATEGORY_LABELS` egyetlen, központi helyen** (`categorySchemas.ts`) van definiálva.

## Generikus típusbiztos state-frissítés

```ts
const updateField = <K extends keyof GearFormData>(key: K, value: GearFormData[K]) => {
  setForm((prev) => ({ ...prev, [key]: value }));
};
```

A `K extends keyof GearFormData` fordítási időben garantálja, hogy a mezőnév (`key`) és a hozzá tartozó érték (`value`) típusa összeilleszkedjen — elkerülve, hogy pl. egy számot próbálj beírni egy szöveges mezőbe, vagy nem létező mezőnevet adj meg. `GearFormData[K]` a mezőhöz tartozó **típust** kérdezi le az interface-ből, nem a tényleges futásidejű értéket.

## Lépés-navigáció

```ts
const goNext = () => setStep((s) => Math.min(s + 1, TOTAL_STEPS));
const goBack = () => setStep((s) => Math.max(s - 1, 1));
```

A `Math.min`/`Math.max` védi a határokat — a `step` sosem mehet `TOTAL_STEPS` fölé vagy `1` alá, függetlenül attól, hányszor hívják meg a navigációs függvényeket.

## Fotók (1. lépés) — tervezett, még nincs implementálva

**Státusz: stub, funkció nélkül.** A képfeltöltés a Tigris (Fly.io object storage) integrációjától függ, ami egy külön, még el nem kezdett munka. A `gear_images` tábla és a `Gear::images()` reláció megvannak a backend oldalon, de a modal jelenleg nem küld semmilyen kép-adatot — a `POST /api/gears` hívás `attributes: null`-lal fut kategória nélküli esetben is, kép nélkül minden esetben.

## Submit logika

```ts
await api.post('/api/gears', {
  title, description, city, address, price_per_day, category,
  attributes: currentSchema.length > 0 ? form.attributes : null,
});
```

**Miért feltételes az `attributes`:** ha a kiválasztott kategóriának nincs sémája (`hand_tool`), nem küldünk üres objektumot, hanem explicit `null`-t — ez illeszkedik a backend `StoreGearRequest` `prohibited_unless` szabályaihoz, amik semmilyen `attributes.*` kulcsot nem várnak `hand_tool` esetén.
