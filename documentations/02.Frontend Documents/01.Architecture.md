# Frontend Architecture

> **Kapcsolódó dokumentumok:** [02. Pages](./02.Pages.md) · [03. Components](./03.Components.md)

## Stack

- **React 19 + TypeScript**, Vite build
- **React Router v7** — kliens-oldali routing
- **Tailwind CSS v4** — utility-first styling, `@theme` blokkal definiált design-tokenek
- **Axios** — HTTP kliens, Sanctum SPA session-alapú autentikációhoz konfigurálva
- **Headless UI** — akadálymentes, stílus nélküli interaktív komponensek (pl. dropdown)

## Route-struktúra
/login — nyilvános, nincs NavBar
/register — nyilvános, nincs NavBar
/ — védett, Layout-ba ágyazva (NavBar + Home)
/profile — védett, Layout-ba ágyazva (NavBar + Profile)


A védett route-ok egy **szülő route** (`ProtectedRoute`) alá tartoznak, ami:
1. Ellenőrzi az `AuthContext`-ből, van-e bejelentkezett user
2. Ha nincs → `<Navigate to="/login" />`
3. Ha van → rendereli a `Layout`-ot, ami az `<Outlet />`-en keresztül helyettesíti be a konkrét oldalt (`Home` vagy `Profile`)

**Miért ez a felépítés:** a `NavBar`-nak csak a bejelentkezés utáni oldalakon szabad megjelennie — a `Layout` különíti el ezt a réteget, elkerülve, hogy minden egyes oldal saját maga kezelje a fejléc feltételes megjelenítését.

## Autentikáció — `AuthContext`

Session/cookie-alapú (Laravel Sanctum SPA), nem token-alapú. A `main.tsx`-ben az `AuthProvider` az egész alkalmazást körbeöleli, így minden komponens elérheti a `useAuth()` hookon keresztül: `user`, `loading`, `register()`, `login()`, `logout()`.

Induláskor (`useEffect`) a context automatikusan lekérdezi a `/api/me`-t, hogy megállapítsa, van-e érvényes session — ez adja a `loading` állapotot, ami alatt a `ProtectedRoute` várakozik, mielőtt döntene az átirányításról.

## CSRF-kezelés — `lib/axios.ts`

```ts
withCredentials: true,
// cookie-k küldése cross-origin kéréseknél is

withXSRFToken: true,
// XSRF-TOKEN cookie automatikus fejlécbe emelése cross-origin esetén is

xsrfCookieName: 'XSRF-TOKEN',
xsrfHeaderName: 'X-XSRF-TOKEN',
```

`getCsrfCookie()` — a `/sanctum/csrf-cookie` lekérése, amit minden állapotváltoztató művelet (`register`, `login`) előtt meg kell hívni.

## Környezeti változó

`VITE_API_URL` — a backend base URL-je, build-time-ban kerül be a Vite-be. Fly.io-n a `fly.toml` `[build.args]` szekciójában adjuk át, mert a `.env` nem kerül a build-szerverre.
