# Frontend Testing

> **Kapcsolódó dokumentumok:** a backend tesztek a Backend documentations mappa `Testing.md` fájljában, a CI/CD leírás a Program documentations mappában.

## Eszközök

| Eszköz | Szerep |
|---|---|
| **Vitest** | tesztfuttató (a PHPUnit megfelelője), a Vite konfigurációját használja |
| **jsdom** | hamis böngésző-DOM, ebbe renderelődnek a komponensek |
| **React Testing Library** | `render`, `screen`, keresők: a komponenst a felhasználó szemszögéből vizsgálja |
| **user-event** | kattintás, gépelés szimulálása |
| **jest-dom** | olvasható állítások (`toBeInTheDocument`) |

Konfiguráció: a `vite.config.ts` `test` blokkja (`environment: 'jsdom'`, `setupFiles`), a `defineConfig` a `vitest/config`-ból importálva, hogy a `npm run build` típusellenőrzése ismerje a `test` kulcsot. A `src/test/setup.ts` tölti be a `jest-dom` állításait.

Futtatás: `npm test` (`vitest run`: egyszer lefut és kilép, ez kell a CI-hoz is).

## Alapelvek

- **Komponensteszt = a komponens felelősségét teszteli:** mit renderel, mit hív meg, kit értesít. Nem teszteli, hogy a backend jól szűr, vagy hogy az adatbázis átíródott: ez a backend tesztek és a (tervezett) E2E dolga.
- **A hálózat mockolt** (`vi.mock('../../lib/axios')`): a tesztek gyorsak, determinisztikusak, backend és staging nélkül futnak, ezért a CI-ban is megbízhatóak.
- **Arrange – Act – Assert** szerkezet, minden teszt önálló (`beforeEach` + `vi.clearAllMocks()`, a mock válaszát a teszt maga állítja be).
- **Keresés szerep és felirat alapján** (`getByRole`), nem CSS osztály alapján: a stílus átírása nem töri a tesztet.
- **A mock ára:** azt bizonyítja, hogy a komponens a helyes hívást indítja, azt nem, hogy a valódi backend úgy válaszol. Ha egy végpont útvonala változik, a mockolt teszt zöld marad: ezt az E2E fogja meg.

## `GearStatusRow.test.tsx`

| Teszt | Mit ellenőriz |
|---|---|
| draft eszköznél megjeleníti a Közzététel gombot | a gomb látszik `draft` státusznál |
| a megerősítés előtt nem hív API-t | a "Közzététel" kattintás után az `api.patch` nem hívódik |
| a Mégse után eltűnik a megerősítő blokk | a blokk a "Mégse" után nincs a DOM-ban |
| az Igen után egyszer hívja a PATCH-et a helyes adattal | `PATCH /api/gears/5/status`, `{ status: 'available' }`, pontosan egyszer |
| az Igen után értesíti a szülőt | az `onStatusChanged` callback meghívódik (`waitFor`-ral, mert aszinkron) |

## CI

A `frontend.yml` `build` jobja az `npm run build` után az `npm test`-et is futtatja, ezért a `build` kötelező check a tesztek eredményét is magában foglalja.
